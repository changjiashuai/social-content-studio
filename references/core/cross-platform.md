# 跨平台一致性 cross-platform

用户同时选了多个平台或多个形式时用本文件。目标：**口径一致、素材只做一次、发布互相导流**。

---

## 1. 派生关系（先事实源，后派生）

```
产品取材（视频线第 3 步，只做一次）
        │
        ▼
   DIRECTION.md（跨平台共用主视觉与口号）
        │
        ├──▶ ① 事实源（见 core/routing.md §5.1：通常是公众号长文 / 小红书图文正文）
        │            │
        │            ├──▶ ② 静态切片：微信图文、小红书图文笔记
        │            └──▶ ③ 动态切片：视频号视频、小红书视频笔记
        │
        └──▶ ④ 通用产品片（原视频线；横版 16:9，可作其他形式的素材来源）
```

**规则**：
- 事实源是所有形式的**唯一**口径出处。任何形式里出现的数字，必须能在事实源里查到出处。
- 不允许"先做视频再倒推长文"——那样长文会变成视频脚本的注水版，可信度最低而它本该是可信度最高的载体。
- 只有通用产品片时，独立走视频线原生流程，不受本文件约束。

## 2. 一致性清单（交付前逐项过）

| 维度 | 必须一致 | 允许分叉 |
|---|---|---|
| 主色 / 字体 / 图形母题 | ✅ 跨平台完全一致 | — |
| 产品口号与一句话定位 | ✅ 逐字一致 | — |
| 关键数字（体积、性能、版本号） | ✅ 逐字一致 | 事实源可给更多小数位与测量条件 |
| 数据主张的免责 / 口径说明 | ✅ 都存在 | 长文写完整句；图文与视频写可核对的简称 |
| 版本号与功能名 | ✅ 一致 | — |
| 信息密度 | — | 公众号 3000–5000 字 / 小红书图文正文 400–600 字 / 微信图文 6–9 张 / 视频 30–90 秒 |
| 画幅与排版 | — | 公众号内联样式、两平台的图文均 3:4、视频 9:16 或 16:9 |
| 语言风格 | — | 公众号可专业，小红书与视频更口语、更有个人视角 |
| 话题 / 标签 | — | 小红书必须有话题标签，微信公众号没有这个概念 |
| 平台合规措辞 | — | 小红书禁用站外导流（见 §4.3），微信不禁；同一句话可能在一端合规、在另一端违规 |

**红线**：不允许为了短视频的传播力删掉免责说明或夸大数字。视频线硬约束「真实功能」与「数据口径说明同步进文案」在这里继续生效。

## 3. 素材复用

### 3.1 一张主视觉出所有画幅

沿用视频线第 25–28 条。一次产出可能需要的画幅：

| 用途 | 尺寸 | 比例 | 模板 |
|---|---|---|---|
| 微信图文卡 | 1080×1440 | 3:4 | `assets/platforms/wechat/image-text/card.template.html` |
| 公众号头条封面 | 900×383 | 2.35:1 | `assets/platforms/wechat/article/cover-235.template.html` |
| 公众号次条封面 | 500×500 | 1:1 | `assets/platforms/wechat/article/cover-11.template.html` |
| 视频号竖版封面 | 1080×1260 | 6:7 | `assets/platforms/wechat/channels/cover-67.template.html` |
| 视频号横版封面 | 1080×608 | 16:9 | 同上，改画布尺寸 |
| **小红书图集页 / 封面** | 1080×1440 | 3:4 | `assets/platforms/xiaohongshu/image-text/note.template.html` |
| **小红书视频封面** | 1080×1440 | 3:4 | `assets/platforms/xiaohongshu/video/cover-34.template.html` |
| （若有通用产品片） | 3:4 / 4:3 / 16:9 | — | 视频线 `cover.mjs` |

**做法**：把所有画幅的卡片放进**同一个 HTML 页面**并排（`display:flex`），渲染器 `viewport` 放大到能容纳全部卡片，再对每个元素 `el.screenshot()` 单独出图。改一处文案 → 所有画幅同步。详见视频线第 69 行的封面做法。

> 微信图卡与小红书图集页都是 3:4，**可以复用同一套版式思路但不要复用同一个文件**——两者的安全区、字数上限、页脚元素不同（小红书要留话题标签位，微信图卡要避开前 3 张的 2.35:1 裁切）。

### 3.2 视频素材多用

- 视频号 / 小红书视频成片可导出关键静帧 → 两端图文的配图或背景。
- 视频号的成片要做竖版化处理时，同一份横版素材可同时服务两个平台（加黑边 + 各自封面）。
- 通用产品片的横版成片 → 视频号 / 小红书"竖版化处理"（加黑边 + 竖版封面）。

## 4. 发布顺序与互相挂载

### 4.1 推荐顺序（也是素材依赖顺序）

1. **事实源先发**（通常是公众号长文）—— 它要给其他形式提供可挂载的链接与口径。
2. **静态切片随后**（微信图文 / 小红书图文笔记）。
3. **动态切片最后**（视频号 / 小红书视频）—— 用视频抓人，指向事实源给信任。

### 4.2 微信内部挂载

- 视频号描述 → 公众号文章链接（官方支持，是主要导流入口）
- 长文正文 → 视频号视频（在正文里插入视频号内容或引导语）
- 微信图文 → 长文（图片消息**不支持外链**，只能在配套文案里提"详细版见公众号文章"）

### 4.3 跨平台挂载（重要：两个生态是隔离的）

| 关系 | 可行性 |
|---|---|
| 微信公众号 → 小红书 | 公众号正文可提"小红书同名账号"，但**不要直接贴小红书链接**（公众号外链仅限白名单域名，小红书链接通常不可点） |
| 小红书 → 微信公众号 | ❌ **不要做**。小红书对站外导流（微信号、二维码、"vx/vxin"、其他平台链接）查得很严，轻则限流重则处罚 |
| 小红书笔记之间 | ✅ 可以用话题标签串起同系列笔记（平台内合规的串联方式） |

**结论**：跨平台时，**不要设计互相导流**，改成"同一主视觉 + 同一口号 + 各平台各说各的"。让用户在两个平台都认出是同一主体，而不是让内容互相跳转。

## 5. 交付清单（多选时）

```
export/
├── wechat/
│   ├── mp-article/    # article.html + 两张封面 + meta.json + copy.md + check.json
│   ├── image-text/    # 01..NN.jpg + meta.json + copy.md + check.json
│   └── channels/      # final.mp4 + cover-67.jpg + meta.json + copy.md + check.json
├── xiaohongshu/
│   ├── image-text/    # 01..NN.jpg + cover-34.jpg + meta.json + copy.md + check.json
│   └── video/         # final.mp4 + cover-34.jpg + meta.json + copy.md + check.json
├── generic/
│   └── product-video/ # （若选了通用产品片）final.mp4 + 三画幅封面
└── consistency.md     # 一致性核对表（第 2 节那张表的填好版）+ 发布顺序 + 挂载关系 + 未核实项
```

`consistency.md` 是多项时的**必交项**——多端最大的风险不是单端质量差，而是几端说了几个不同的数字。
