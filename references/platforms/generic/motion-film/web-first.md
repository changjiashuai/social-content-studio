# 网址优先：拿不到源码时怎么调查

大多数产品片开工时**没有仓库**——可能是 SaaS、刚发布的项目、竞品、客户只给了一个官网。这时 [仓库与风格审计](repo-and-style.md) 那条路径走不通，但**「不伪造」的硬约束依然成立**。

这一页定的是：只有网址时，能调查到什么、由此能做什么片子、以及哪些事不能做。

---

## 1. 先判证据级别（这决定整支片子的能力边界）

调查开始前先回答一句：**我手上有哪一级证据？** 级别决定可用形状，不能倒过来先定形状再找证据。

| 级别 | 手上有什么 | 能接原组件 | 能演示真实交互 | 片子定位 |
|---|---|---|---|---|
| **A · 仓库** | 可访问的源码 | ✅ | ✅ | 完整功能演示 |
| **B · 素材** | 用户给的截图 / 录屏 / 设计稿 | 只能忠实复用画面 | 录屏能，其余不能 | 以界面为主 |
| **C · 网址** | 只有公开页面 | ❌ | ❌ | **主张 + 证据型** |

**证据级别是上限，不是下限。** C 级不是「差一点的 A 级」，它是一支**不同类型的片子**：讲清产品是什么、凭什么值得信、解决了什么，而不是演示怎么点。

级别写进 `RESEARCH.md`，也写进 `plan.json` 的 `evidenceLevel`（`repo` / `material` / `web`）。

---

## 2. C 级：从公开网址能拿到什么

按顺序挖，每一类都记下来源 URL（进 `evidence/FACTS.md`）：

| 来源 | 拿什么 | 常见坑 |
|---|---|---|
| **官网首页** | 一句话定位、主张、核心价值、目标用户 | 营销话术要翻译成人话，不要直接搬上屏 |
| **产品页 / 功能页** | 功能清单、能力边界、支持矩阵 | 功能页写的不等于已上线，找状态说明 |
| **定价页** | 版本分层、限额、目标客户画像 | 价格会变，记下抓取日期 |
| **文档站** | 术语、架构、API 形态、真实字段名 | 文档最可信，也最适合做机理类镜头的原料 |
| **Changelog / Release Notes** | 版本节奏、最近做了什么、发布状态 | 这是「更新片」唯一可靠的公开依据 |
| **博客 / 官方公告** | 动机、里程碑、用户案例（注意区分官方与第三方） | 客户案例的数字通常有口径，别当成自己的数据 |
| **公开数据集 / 基准测试** | 可复核的数字、评测结果 | 只引用能公开访问且可核对的 |
| **公开 GitHub 仓库**（若有） | README、stars、release、issue 里的真实痛点 | 有仓库就升到 A 级，别浪费 |
| **应用商店页** | 截图、更新说明、评分分布 | 截图可作为 B 级素材 |

### 内容挖掘的三层

1. **事实层**：公司是什么、产品是什么、谁在用、多少钱 → 进 RESEARCH.md 的「事实」。
2. **证据层**：可公开引用的数字与断言（带 URL 与原文）→ 进 `FACTS.md`。
3. **叙事层**：从事实推出「这支片子该讲哪一个点」→ 进 RESEARCH.md 的「结论」。

三层缺任何一层都不许进 [影片方向](direction.md) 第 3 节。

---

## 3. 三条硬线

**① 只用公开可引用的内容。**
官网、公开文档、公开数据集、公开发布记录、公开仓库。引用要能回到原页面，原文进 `FACTS.md`。

**② 绝不使用以下内容。**
需要登录/付费墙后的内容、泄露的内部资料、竞品未公开的路线图、用户私域数据、任何「看起来像内部截图」的东西。**也不推测**「他们大概即将发布 X」并当成事实讲。

**③ 不假造界面。**
C 级没有原组件，就**不做功能演示镜头**。想表达「用起来是这样」，用下面这些替代：

| 想表达 | 允许的做法 | 不允许 |
|---|---|---|
| 界面长什么样 | 用官方公开截图（B 级素材）并标明来源 | 自己画一个"像但不准"的界面 |
| 功能怎么用 | 讲清机理（Mechanism）或价值（Claim） | 摆出可点击的假 UI |
| 数据表现 | 引用公开数字 + 出处 | 造一组「示意但看起来像真的」曲线 |
| 架构与集成 | 用官方文档的架构描述重画示意图 | 假装是产品内的实时图 |

**降级是正当的，伪装不是。** 一支诚实的 C 级片子，比一支假装演示的 A 级片子更可信。

---

## 4. C 级能做什么形状（与风格推导衔接）

证据级别直接约束能选的信息形状，**不要越级**：

| 形状 | A 级 | B 级 | C 级 | 说明 |
|---|---|---|---|---|
| Claim / 主张 | ✅ | ✅ | ✅ | 官网主张最可靠 |
| Evidence / 证据 | ✅ | ✅ | ✅ | 公开数字可引用 |
| Mechanism / 机理 | ✅ | ✅ | ✅ | 文档站是最好原料 |
| List / 清单 | ✅ | ✅ | ✅ | 功能/版本清单 |
| Transformation / 转变 | ✅ | ✅ | ⚠️ | C 级只能讲「产品带来的变化」，不能演前后真实状态 |
| Story / 故事 | ✅ | ✅ | ⚠️ | 需虚构角色时，明确是示意 |
| Workflow / 流程 | ✅ | ⚠️ | ❌ | 需要真实操作，C 级做不到 |
| Showcase / 展示 | ✅ | ✅ | ⚠️ | 只能用公开素材，不能深做一件自己的作品 |

越级是 C 级片子最常见的失败原因：明明只有官网，却想演「你点一下这里」。

---

## 5. 完成标准

C 级调查做完的标志：`RESEARCH.md` 能回答下面四个问题（契约见 [调研摘要](research-brief.md)）。

1. 这个产品**用官网自己的话**是什么？
2. 有哪些**可公开引用的**数字或事实？（每条带 URL）
3. 证据级别是什么，因此**不能做**什么？
4. 一句话：这支片子讲什么？

四个问题答不上来，说明调查不够，不要进下一步。

---

## 6. 工具与坑

- 抓取优先用 `curl` / WebFetch；无头浏览器联网常被杀（见 [本机实测管线](pipeline-notes.md) 第 8/14 条）。
- 站点多是 SPA：直接抓 HTML 拿不到内容时，抓 `grep -E '--color-|"title"|og:'` 找设计变量与元信息，或从 sitemap / `/robots.txt` 找真实路由。
- 图片素材优先用官方公开的 OG 图、press kit；**不使用**带其他平台水印的图。
- 页面改版会让链接失效：抓取日期写进 `FACTS.md`，否则半年后自己都核对不了。
- 遇到付费墙就停，按硬线②处理，不要绕过。

---

## 7. 用户后来给了源码怎么办

随时可以**升级证据级别**：A 级出现后，把 C 级的推断项逐条复核，能替换成原组件就替换，替换不了的保留并说明。升级要记进 `BRIEF.md`——不要默默改口径。
