**载体**：微信视频号。
**交付物**：成品 mp4 + 封面（竖版 1080×1260 / 横版另出）+ 描述文案 + 短标题候选 + 话题与挂载建议。

规格见 [微信官方规格总表](specs.md) 第三节。**本线大部分能力直接复用视频线**，本文件只写差异。

## 2. 画幅决策（必须在分镜之前定死）

视频号要求宽高比落在 **0.33 ~ 3.0**，官方建议用**标准比例 9:16 或 16:9**。三选一：

| 方案 | 何时用 | 代价 |
|---|---|---|
| **竖版 9:16（1080×1920）** | 想要最大占屏、主体是人物/单一界面、信息流里视觉冲击强 | 桌面端观看体验差；宽屏 UI 截图会被压得很窄 |
| **横版 16:9（1920×1080）** | 内容主体是宽屏界面/代码/图表，或要同时当官网/发布会素材 | **视频号主页会把封面裁成 6:7**，必须单独做竖版封面（见第 4 节） |
| **竖版化处理（横版素材 + 上下黑边 → 9:16 或 6:7）** | 已有横版成片、想稳稳发视频号 | 有效画面变小；黑边上可放标题/字幕，反而更好读 |

**决策规则**：产品主体是"宽屏界面演示"时，**不要**硬做竖版 9:16——界面被压窄比黑边更难看。此时选"竖版化处理"，把横版画面居中放置，上下黑边做标题与关键帧。

画幅确定后写入 `plan.json.formOptions["wechat/channels"].aspect`，**后续分镜只按这个画幅做，不允许中途改**。

## 3. 导出参数与编码兼容

```sh
ffmpeg -framerate 25 -i frames/f%05d.jpg -i mix.wav \
  -c:v libx264 -profile:v high -crf 18 -pix_fmt yuv420p -movflags +faststart \
  -b:v 12M -maxrate 16M -bufsize 24M \
  -c:a aac -b:a 192k -shortest out.mp4
```

- **编码选 H.264**：H.265 在 Windows 的 Chrome/Edge 上不能播放，用户只能用 Mac Safari 上传。除非用户明确只用 macOS，否则默认 H.264。
- **码率 ≥10Mbps**：官方建议 10Mbps 以上。1080p25/30 用 `-crf 18` + `-maxrate 16M` 基本能落在 10–16Mbps。
- **`yuv420p` + `faststart`**：保证全平台可播、支持边下边播。
- **分辨率 ≥1080p**；不要"导出 720p 省体积"——信息密集的产品界面在 720p 下文字不可读。
- **体积自查**：手机端 ≤2GB。导出后 `ls -l` 看实际大小；超了先砍时长再降码率，不要先降分辨率。
- **时长**：手机端 3 秒 ~ 60 分钟，助手端 3 秒 ~ 8 小时。产品短片建议 **30–90 秒**（超过 60 秒完播率明显下降，但这是经验值不是官方红线）。

## 4. 封面

- **竖版封面 1080×1260（6:7）**：模板 `assets/platforms/wechat/channels/cover-67.template.html`。
- **横版封面 1080×608（16:9）**：横版视频用，但**主页列表仍会裁成 6:7** → 关键信息（标题、数字）必须收进 6:7 中心安全区。
- **首帧即封面**：视频号封面默认从视频里选帧。所以视频线「**首帧就是完整画面**」的硬约束在这里是**强制**的——第 1 帧不能是空白底色或等待入场的背景，要放开场段落的完成态。这条与视频线完全同源。
- **深底封面要压暗 HUD 区**：沿用视频线第 26 条（白色 HUD 压在亮色纹理上不可读，需加 ~210px 顶部渐变 scrim）。
- **一图多画幅**：竖版封面与横版封面用同一张主视觉，通过 `background-size` / `background-position` 裁不同画幅（视频线第 25 条：先确认主视觉底色与主色一致，才能任意裁切不出现接缝）。

## 5. 描述与短标题

### 5.1 描述（≤1000 字）

- **前两行是全部**：超过三个非空白行会自动折叠，钩子必须在折叠线以上。
- 结构建议：第 1 行给结论/亮点（带数字）→ 第 2 行给"看完能得到什么" → 空行 → 正文补充（技术细节、怎么用）→ 话题 `#xx#` → @提及与位置 → **公众号文章链接**（多端联动时这是主入口）。
- 不复述视频里已经说过的每句话——描述是补充信息与导流，不是字幕。

### 5.2 短标题（≤16 字）

**必须单独打磨**，不要从描述里截前 16 字。

- 短标题会出现在**搜索 / 话题 / 活动 / 地点 / 订阅号消息**等场景——它是搜索入口，写法接近 SEO 标题：**具体对象 + 具体结果**。
- 好：`打包体积砍到 48MB`。差：`我们做了一次优化`。
- 给 3 条候选，逐条数字符数（中文字符按 1 计，标点也算）。

## 6. 自检

```sh
python3 <skill-dir>/scripts/check_social_delivery.py --project <content-dir> --forms wechat/channels --strict
```

检查项：成品时长在 3 秒 ~ 上限内、体积 ≤2GB（手机端口径）、分辨率 ≥1080p、宽高比落在 0.33~3.0（并提示是否接近推荐的 9:16 / 16:9）、编码为 H.264、封面尺寸（竖版 1080×1260 / 横版 1080×608）、描述 ≤1000 字、短标题 ≤16 字、**第 1 帧非空白**（沿用视频线 `check_delivery.py` 的前 5 帧检测）。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传后提示不支持 | H.265 在 Windows 浏览器无法播放/解析 | 重导 H.264；或提示用户用 Mac Safari 上传 |
| 主页封面文字被切掉 | 横版封面的信息落在 16:9 边缘，主页裁成 6:7 后丢失 | 信息收进 6:7 中心区，或单独出竖版封面 |
| 视频在信息流里缩略图是黑屏/空背景 | 第 1 帧是空白底色或入场前的等待态 | 前 5–10 帧放开场段落的完成态（视频线硬约束「首帧就是完整画面」） |
| 描述发出去后半截没了 | 超过三行被自动折叠 | 钩子放前两行；详细内容改放公众号文章 |
| 搜不到自己的视频 | 没填短标题或短标题太泛 | 填 ≤16 字的"对象+结果"式短标题 |
| 体积超 2GB | 时长过长或码率过高 | 先砍时长，再降 `-crf` / `-maxrate`，最后才考虑降分辨率 |
