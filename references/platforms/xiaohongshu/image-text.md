# 小红书图文笔记

**形式 ID**：`xiaohongshu/image-text`
**载体**：小红书图文笔记（图集 + 标题 + 正文 + 话题）
**交付物**：3:4 图集（含封面） + 标题候选（≤20 字） + 正文 + 话题标签 + 自检报告。

规格以 [小红书规格总表](specs.md) 第一节为准；本文件讲**怎么做**。

---

## 1. 与微信图文的差别（同是 3:4 图集，逻辑完全不同）

| | 微信图文（图片消息） | 小红书图文笔记 |
|---|---|---|
| 分发逻辑 | 订阅关系，读者已关注你 | 信息流 + 搜索，先抢点击再吃搜索长尾 |
| 首图职责 | 承担封面，但要避开 2.35:1 裁切 | 承担封面，**且是点击率的唯一决定因素** |
| 文字载体 | 图上文字 ≤60 字 + 配套文案 | 图上大字 + 标题 ≤20 字 + 正文 ≤1000 字 |
| 话题 | 无此概念 | **必须有 5–15 个话题**，是主要流量入口 |
| 语气 | 可专业、可企业向 | 必须口语、有个人视角（"我实测"优于"本产品"） |
| 导流 | 不支持外链 | **严禁站外导流**（微信号/二维码都不行） |
| 图片体积 | ≤10MB | ≤20MB |

**一句话**：微信图文是"给已关注你的人递一份说明"，小红书图文是"在信息流里用首图抢一次点击，再用话题接住搜索"。

## 2. 步骤

### 2.1 定选题与骨架

先写一句话骨架，再拆张。三种可用骨架（与微信图文同源，但**第 1 张的钩子要更狠**）：

- **问题 → 拆解 → 结果**：第 1 张抛出痛点（带具体数字），中间拆成因，末尾给结果与数据。
- **清单 1..N**：N 个技巧/好物并列，第 1 张给"看完能得到什么"。
- **单点深挖**：1 个点讲透，3–5 张。

**张数**：推荐 **6–9 张**（上限口径不一，见规格表）。

### 2.2 出图（3:4）

- **画布**：1080×1440（3:4）。尺寸从 `scripts/social_specs.json` 读，不要手写。
- **版式**：用 `assets/platforms/xiaohongshu/image-text/note.template.html`。它提供顶部系列条 / 中部钩子+要点 / 底部话题位三段结构，以及中心安全区导引。
- **整篇同一比例**：所有图都用 3:4，混用会导致滑动跳版（自检会比对首图比例）。
- **文字可读性**：按真实像素算，正文 ≥32px、标题 ≥72px（1080 宽画布）。信息流里图很小，小字等于没有。
- **风格**：主色/字体/图形母题从 `DIRECTION.md` 读，跨平台保持一致；但**不要复用视频线的镜头手法**（发光地平线、粒子汇聚这类），静态排版硬套动态手法会变成无意义装饰。

### 2.3 封面（首图）

首图即封面，单独按封面标准设计：

- **大字结论**：一行能读完的主张 + 一个具体数字（1080 宽画布上标题 ≥72px）。
- **主体物**：一个能一眼看懂的对象（产品/界面/对比图），不要纯文字排版。
- **中心安全区**：信息流可能按更窄比例裁切，关键信息留在中心 86% 区域内（模板有 `#safe-center` 导引，导出时自动隐藏）。
- **不放二维码、不放联系方式**——这是红线。

### 2.4 标题（≤20 字）

**前 10–12 字是全部**，列表页会截断。

- 好：`首屏快 3 倍，我只改了一个配置`（对象 + 结果，前 12 字已完整）。
- 差：`关于前端性能优化的一些思考与总结`（没对象、没结果、前 12 字什么也没说）。

给 3 条候选，逐条数字符数（表情符号按 2 个字符计）。

### 2.5 正文（≤1000 字，建议 100–400 字）

- **前 2–3 行是推荐与搜索的抓取重点**，钩子必须放在最前，不要写"最近很多姐妹问我"。
- 分点、加 emoji、留空行——手机上一大段密字没人看。
- 具体 > 抽象：给数字、给步骤、给对比。
- **每个数字都要能回溯**（视频线硬约束「真实功能」）：在 `claims.md` 里记下来源。
- **不写站外导流**：不提微信、二维码、"私信发你"之外的站外路径。

### 2.6 话题标签（5–15 个）

按层级选：

| 层级 | 数量 | 例子 | 作用 |
|---|---|---|---|
| 核心标签 | 1–2 | `#前端性能优化` | 直击目标人群 |
| 场景标签 | 3–5 | `#程序员日常` `#技术分享` | 绑定使用场景 |
| 长尾标签 | 2–8 | `#首屏优化` `#打包体积` | 提高搜索精准度 |

不滥用无关热门标签（会被判违规且稀释精准度）。

### 2.7 自检

```sh
python3 <skill-dir>/scripts/check_social_delivery.py --project <content-dir> --forms xiaohongshu/image-text --strict
```

检查项：张数上限与建议区间、每张比例是否 3:4、**全篇比例是否一致**、单图体积 ≤20MB、分辨率提示、标题 ≤20 字、正文 ≤1000 字、话题 5–15 个、**风险词扫描**（导流词 + 绝对化用语）。

## 3. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 点击率低 | 首图是纯文字或信息太杂 | 首图改成"大字结论 + 主体物"，一个图只说一件事 |
| 滑动时版式跳动 | 图集里混了不同比例 | 全部统一成 3:4（自检的「比例一致性」会报） |
| 笔记没流量 | 没加话题，或话题与内容无关 | 按核心/场景/长尾三层补 5–15 个话题 |
| 被判违规/限流 | 出现微信号、二维码或绝对化用语 | 全篇排查；`copy.md` 与 `meta.json` 会被脚本扫一遍 |
| 标题在列表页被截断 | 前 12 字没放核心信息 | 把对象 + 结果提到最前 |
| 图片发虚 | 原图小于 720×960 | 按 1080×1440 出图，交付前用脚本读真实像素核对 |
| 用了拼音替代敏感词 | 平台会识别拼音代字 | 换表达方式，不要用拼音绕 |

## 4. 交付清单

- `export/xiaohongshu/image-text/01..NN.jpg`（3:4，按滑动顺序命名；01 即封面）
- `export/xiaohongshu/image-text/cover-34.jpg`（可选：若单独另做封面）
- `export/xiaohongshu/image-text/copy.md`：标题候选 3 条（各 ≤20 字，标注字数）+ 正文全文 + 话题清单（含分层说明）
- `export/xiaohongshu/image-text/meta.json`：**自检脚本读它来校验字数、话题与风险词**，必须交付：
  ```json
  {
    "form": "xiaohongshu/image-text",
    "title": "首屏快 3 倍，我只改了一个配置",
    "bodyChars": 286,
    "topics": ["#前端性能优化", "#程序员日常", "#技术分享", "#首屏优化"]
  }
  ```
- `export/xiaohongshu/image-text/check.json`：自检实测结果
- `claims.md`：图文中出现的数字与来源对照（无出处的数字不许用）
- 一句风险声明：哪些主张有出处、哪些是定性表述、哪些数字无法自证因此未使用
