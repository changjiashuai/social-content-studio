# 小红书视频笔记

**形式 ID**：`xiaohongshu/video`
**载体**：小红书视频笔记（竖屏成片 + 3:4 封面 + 标题 + 正文 + 话题）
**交付物**：成品 mp4（9:16）+ 3:4 封面 + 标题（≤20 字）+ 正文 + 话题 + 自检报告。

规格以 [小红书规格总表](specs.md) 第二节为准。**本形式大部分能力直接复用视频线**，本文件只写差异。

## 1. 与视频号视频的差别（都是竖屏视频，落点不同）

| | 微信视频号 | 小红书视频笔记 |
|---|---|---|
| 分发逻辑 | 社交推荐 + 关注，朋友圈/群传播强 | 信息流 + 搜索，靠封面与标题抢点击 |
| 封面比例 | 6:7（1080×1260） | **3:4（1080×1440）** |
| 封面来源 | 默认从视频选帧（所以首帧必须完整） | **编辑页单独设置**（不要用首帧） |
| 描述长度 | ≤1000 字，超三行折叠 | ≤1000 字，建议 50–200 字 |
| 短标题 | ≤16 字，进搜索场景 | 无短标题概念，标题 ≤20 字 |
| 话题 | `#xx#` 可挂载 | **必须有 5–15 个话题**（主要流量入口） |
| 导流 | 可挂公众号文章链接 | **严禁站外导流** |
| 运营重点 | 社交传播 | 封面 + 标题 + 话题三件套 |

**一句话**：视频号靠"关系链 + 首帧"，小红书靠"封面 + 标题 + 话题"。同一支成片，两端的封面与文案必须分别做。

## 2. 步骤

### 2.1 先定画幅（在分镜之前）

- 首选 **9:16（1080×1920）**——小红书最推荐、占屏最大。
- 已有横版素材时：**加黑边做成 9:16**，而不是硬拉伸或直接发横版（横版在小红书信息流占屏小、完播差）。
- 画幅定完写进 `plan.json.formOptions["xiaohongshu/video"]`，**分镜只按这个画幅做**。

### 2.2 复用视频线第 4–7 步

| 环节 | 处理 |
|---|---|
| 产品取材、真实功能主张 | **完全复用**视频线第 3 步 |
| `DIRECTION.md`（方向、专属手法、画面规范、镜头表） | **完全复用**视频线第 4 步 |
| 逐镜头搭建、GSAP 时间轴 | **完全复用**视频线第 5 步 |
| 配乐与音效、混音、loudnorm | **完全复用**视频线第 6 步与第 21/22 条 |
| 渲染管线（无头 Chrome + ffmpeg） | **完全复用**视频线本机实测管线 |
| 审片 | **完全复用**视频线第 7 步 |

### 2.3 导出参数

与视频号同一条底座（H.264 + yuv420p + faststart），按小红书调整目标：

```sh
ffmpeg -framerate 30 -i frames/f%05d.jpg -i mix.wav \
  -c:v libx264 -profile:v high -crf 18 -pix_fmt yuv420p -movflags +faststart \
  -b:v 10M -maxrate 14M -bufsize 20M \
  -c:a aac -b:a 192k -ar 44100 -shortest out.mp4
```

- **H.264 + AAC**：小红书推荐编码，跨端稳妥。
- **帧率 25–30**：与源帧率一致，不插帧。
- **短边 ≥1080px**：1024 宽这类会发虚（自检按短边判）。
- **时长**：30 秒–3 分钟最稳；上限口径不一（见规格表）。

### 2.4 封面（必须单独做，3:4）

- 画布 **1080×1440（3:4）**，模板 `assets/platforms/xiaohongshu/video/cover-34.template.html`。
- **不要用视频首帧**：首帧比例通常对不上 3:4，且没排版。
- 封面三要素：**大字结论**（一行读完，带数字）+ **主体物**（产品/界面/对比）+ **高对比底色**。
- 关键信息压在中心安全区（信息流可能按更窄比例裁切）。
- 视频内也不要出现其他平台水印——封面与正片都要干净。

### 2.5 标题 / 正文 / 话题

- **标题 ≤20 字**，前 10–12 字是钩子（同图文笔记规则）。
- **正文 ≤1000 字**，建议 50–200 字：第 1 行给结论，第 2 行给"看完能得到什么"，后面补充细节。
- **话题 5–15 个**，按核心/场景/长尾分层（见 [图文笔记](image-text.md) §2.6）。
- **不写站外导流**：不提微信、不放二维码。

### 2.6 前 3 秒

小红书完播高度依赖开头。**第 1 秒就要进入内容**，不要 logo 动画、不要"大家好我是…"。

> 这与视频线「首帧就是完整画面」的硬约束同源，但小红书更严：**首帧不只是要完整，还要直接是钩子本身**（结论/对比/最抓人的一幕）。

### 2.7 自检

```sh
python3 <skill-dir>/scripts/check_social_delivery.py --project <content-dir> --forms xiaohongshu/video --strict
```

检查项：成品体积、时长区间、宽高比（是否接近 9:16）、**短边分辨率 ≥1080**、编码 H.264、像素格式、帧率 25–30、音轨、**3:4 封面是否存在且比例正确**、标题 ≤20 字、正文 ≤1000 字、话题 5–15 个、**风险词扫描**。

## 3. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 封面在信息流被裁掉一半 | 直接用了视频首帧或横版封面 | 单独做 1080×1440 的 3:4 封面 |
| 完播率低 | 开头 3 秒是 logo/片头/问候 | 第 1 帧直接给结论或最强画面 |
| 没有流量 | 没加话题 | 补 5–15 个分层话题 |
| 被判导流 | 视频内或正文出现微信号/二维码/其他平台 | 全片 + 文案排查，去掉所有站外信息 |
| 视频模糊 | 导出分辨率低于 1080p 或码率太低 | 按 1080×1920 出图，码率提到 10Mbps |
| 横版素材发上去占屏小 | 直接发横版 | 加黑边做成 9:16 竖版 |
| 时长超限被拒 | 超过平台上限 | 上限口径不一，交付前先按编辑器提示核对；长内容拆成系列 |
