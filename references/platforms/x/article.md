# X 文章（Article）

`x/article` ｜ 长篇公开写作：一次说清一件事，且经得起被引用。

---

## 1. 形态

一道独立页面，从时间线点击进入。有标题、封面、分节结构、图片与列表；正文最长约 10 万字符（以编辑器实际提示为准，见 [specs](specs.md) §1.1）。

**与长帖的分界**：讲一个完整观点 → 长帖；需要标题、分节、证据链 → Article。判据是**有没有结构**，不是字数。

---

## 2. 流程

1. **定论点**（一句话）。写不出这句话就不要开写——Article 的失败几乎都是「什么都讲了，什么都没说清」。
2. **找证据**。每条数据、每个断言落到 `evidence/FACTS.md`（[内部溯源](../generic/motion-film/provenance.md)），状态标 `已核实` / `示意` / `待核实`。
3. **搭结构**。三到五节，每节一个论点，节标题能独立成句。
4. **写开头**（见 §3）与**写结尾**。
5. **配图与封面**：封面 16:9；正文图与论点相邻，不堆图。
6. **自检**（见 §5），再过一遍手机阅读。

---

## 3. 开头第一段承担全部钩子

Article 不在时间线内展开，用户先看到的是**标题 + 封面 + 第一段**。所以：

- 第一段必须在 **2–3 句内**说清「这篇解决什么问题 / 讲了什么」。
- 不放「最近很多人问我」「先说说背景」这类铺垫。
- 第一段同时是**时间线摘要**——它决定有没有人点进来。

**反面**：「随着 AI 的发展，越来越多的团队开始关注……」——这种开头在任何平台的完读率都低。

---

## 4. 写作要点

### 结构

- 节标题写**结论**，不写分类词。「三种方案各有代价」优于「方案对比」。
- 每节 3–6 段；超过 8 段就再分一节。
- 长文在前三分之一给一次**小结论**，让读者知道值得往下读。

### 语言

- 中文正文用系统字体渲染（`-apple-system` / `PingFang SC` / `Microsoft YaHei`），不加载外部字体。需要特殊字体时，把那一段做成图。
- 中英混排时中英文之间留空格；专有名词首次出现给英文原文。
- 术语先解释再用，别用行话省字。

### 格式的使用纪律

支持标题、粗体、列表不等于都该用：

| 元素 | 什么时候用 | 什么时候不用 |
|---|---|---|
| 粗体 | 标记关键结论，全文 ≤ 10 处 | 整段加粗（等于没加） |
| 列表 | 步骤、并列项、清单 | 需要论证的段落（列表讲不了因果） |
| 分节标题 | 每节一个 | 节内小节再套标题（层级过深） |
| 图片 | 与论点相邻、有信息量 | 装饰性配图、纯截图堆叠 |
| 嵌入帖子 | 引用他人原话作为证据 | 借别人的热度 |

### 话题标签

X 的标签文化与小红书不同。**正文里堆标签会显得外行**；确有必要时用 1–2 个与主题强相关的，放在文末。

---

## 5. 常见问题

| 现象 | 通常的原因 | 改法 |
|---|---|---|
| 发出去没人点 | 标题或第一段没有具体利益点 | 把「我们要讲什么」改成「你能得到什么」 |
| 点进来读两屏就走 | 前三分之一没有小结论 | 在第一节末尾先给一个结论 |
| 看起来很长很累 | 全文一个字号、没有节标题 | 加分节标题；段落压到 3–5 行 |
| 像内部文档 | 术语过多、缺背景 | 术语首次出现给解释；加一个具体例子 |
| 数据被质疑 | 没有出处或口径不清 | 补 FACTS 行；正文给来源与口径 |
| 手机上看排版乱 | 只在桌面检查 | 用手机实际打开编辑器预览 |

## 6. 交付清单

`export/x/article/`：

- `article.md` —— 正文全文（含标题、分节、正文图位置标记）
- `cover-169.jpg` —— 封面，16:9（建议 1200×675 或 1600×900）
- `meta.json` —— **自检脚本读它来校验字数与结构**，必须交付：

```json
{
  "form": "x/article",
  "title": "文章标题（30–70 字符为宜）",
  "intro": "第一段（同时是时间线摘要）",
  "bodyChars": 2400,
  "sections": ["节标题 1", "节标题 2", "节标题 3"],
  "images": 4,
  "link": "https://example.com/related",
  "claim": true
}
```

字段说明：

| 字段 | 必填 | 用途 |
|---|---|---|
| `title` | ✅ | 标题长度校验 |
| `intro` | ✅ | 首段长度与「是否铺垫过久」提示 |
| `bodyChars` 或 `body` | ✅ | 正文字数校验（给了 `body` 取实际长度） |
| `sections` | 建议 | 分节标题；少于 2 个会提示结构过平 |
| `images` | 可选 | 配图数量 |
| `link` | 可选 | 文内主链接 |
| `claim` | 可选 | 是否含事实性主张；为 true 时必须有 FACTS 出处 |

---

## 7. 自检

```sh
python3 <skill-dir>/scripts/check_social_delivery.py --project <content-dir> \
  --forms x/article --strict
```

核对：标题与正文字数、封面比例、`meta.json` 结构、分节数量提示、内部溯源（上屏数字能否在 `evidence/FACTS.md` 找到出处）。

**脚本只证明结构合规**，不证明写得好。发之前自己从手机完整读一遍。
