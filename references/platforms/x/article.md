# X 文章（Article）

`x/article` ｜ 长篇公开写作：一次说清一件事，且经得起被引用。

---

## 1. 形态

一道独立页面，从时间线点击进入。有标题、封面、分节结构、图片与列表；正文最长约 10 万字符（以编辑器实际提示为准，见 [specs](specs.md) §1.1）。

**与长帖的分界**：讲一个完整观点 → 长帖；需要标题、分节、证据链 → Article。判据是**有没有结构**，不是字数。

---

## 2. 流程

1. **定论点**（一句话）。写不出这句话就不要开写——Article 的失败几乎都是「什么都讲了，什么都没说清」。
2. **找证据**。每条数据、每个断言落到 `evidence/FACTS.md`（[内部溯源](../generic/motion-film/provenance.md)），状态标 `已核实` / `示意` / `待核实`。
3. **搭结构**。三到五节，每节一个论点，节标题能独立成句。
4. **写开头**（见 §3）与**写结尾**。
5. **配图与封面**：封面 16:9；正文图与论点相邻，不堆图。
6. **自检**（见 §5），再过一遍手机阅读。

---

## 3. 开头第一段承担全部钩子

Article 不在时间线内展开，用户先看到的是**标题 + 封面 + 第一段**。所以：

- 第一段必须在 **2–3 句内**说清「这篇解决什么问题 / 讲了什么」。
- 不放「最近很多人问我」「先说说背景」这类铺垫。
- 第一段同时是**时间线摘要**——它决定有没有人点进来。

**反面**：「随着 AI 的发展，越来越多的团队开始关注……」——这种开头在任何平台的完读率都低。

---

## 4. 写作要点（官方八条）

下面八条来自 X 官方创作者账号的 [《The ultimate guide to Articles on X》](https://x.com/XCreators/status/2011957172821737574)，是按官方原文重述的检查项。**写完逐条打勾**——它不是建议，是官方给的及格线。

### ① 先定目的

动笔前回答两个问题：

- 读者读完后要 **think / feel / do** 什么？
- 这篇**到底写给谁**？

写不出答案就会写成「什么都讲了」。这个答案写进 `meta.json` 的 `purpose`。

### ② 标题与钩子

官方给的标准：标题要**具体、引发好奇、承诺价值**；配一个强首句把读者带进去。头图同样决定点击，必须**好看且与主题相关**。

| 官方反例 | 官方正例 |
|---|---|
| Tips for Better Productivity in 2026 | **Why 95% of Productivity Advice Fails** |

差别在于：反例是**分类**，正例是**一个具体判断**。

### ③ 为了「可扫读」而排版

官方明确说：**读者是先扫后读的，而且主要在手机上**。五条硬要求：

- 段落 **2–4 行**为上限
- **每 3–5 段**一个小标题
- 列表优于文字墙
- **几乎每一节都要加粗关键洞察**
- 一段只讲一个观点

> 注意这条和我早先写的「粗体全文 ≤10 处」冲突。**以官方为准**：加粗是让扫读者不漏掉价值的手段，不是克制使用的装饰。判断标准是「这一节的关键洞察有没有被加粗」，不是数量上限。

### ④ 自然、可辨认的声音

语气一致（分析型 / 犀利 / 对话型都可）会让读者记住你。官方原话：**一旦写得太「专业」，它通常就变无聊了**。用「你」「你的」这类对话语言。

| 官方反例 | 官方正例 |
|---|---|
| Successful people always prioritize their tasks. | **You need to stop doing everything — focus on the 3 things that actually move the needle.** |

### ⑤ 展示，而不只是陈述

每个主张**紧跟证据**：数据、个人经历、前后对比、你自己的旧帖或旧文章作为活例子。这条与内部溯源（`evidence/FACTS.md`）是同一件事的两面——前者管「有没有出处」，这里管「出处放在哪」。

### ⑥ 无情地删

初稿写给自己，第二三稿写给读者。写完必须：

- **砍掉 20–30% 的字数**
- 删掉「非常」「真的」「为了……」这类填充词
- **出声读一遍**——别扭的句子会自己跳出来

这条最容易被跳过，也最直接影响完读率。

### ⑦ 配图与格式

图片、截图、图表、嵌入的帖子能打破文字墙、提升分享。官方观察：**格式好（加粗标题、留白、配图）的文章互动明显更高**。

### ⑧ 强收尾

不要淡出。收尾要有能量，给读者一个**可带走的结论或行动**。官方给三种收法：

- 总结关键点
- **提一个问题**引发回复
- 鼓励对方立刻试其中一条

收尾类型写进 `meta.json` 的 `closeType`。

## 4.1 发布后 72 小时

官方给的增长动作，按时间排：

| 时机 | 动作 |
|---|---|
| 发布前几小时 | 发一条**预热**帖或提问，制造期待 |
| 发布后 **24–72 小时** | 把新文章**置顶**在个人主页（官方特意强调这段时间） |
| 发布后 | 把文章**拆成帖子线程**，用关键摘录引流回全文 |
| 第一时间 | **回复前几个读者** —— 首波互动会提升可见度 |
| 之后任何时候 | 遇到相关新闻周期，**复活旧文**（常青内容可以多次生效） |

---

## 4.2 订阅者可见（变现，可选）

官方发布路径：**Publish → 「Choose your audience」选 Subscribers → 再次 Publish**。

推广给非订阅者时用付费墙链接：

```
https://x.com/YOURUSERNAME/creator-subscriptions/subscribe
```

官方给的订阅内容策略：清楚说明订阅能拿到什么（深度分析 / 提前获取 / 独家观点 / 幕后 / 系列更新）；**软付费墙**——留一些免费文章引流；做订阅者专有形式（周报、行业简报、持仓更新、Q&A）；公开感谢订阅者；结尾预告下期（「Next week:」）建立习惯。

订阅资格在 **Creator Studio** 查看。

---

## 4.3 语言与格式的本地化提醒

- 中文正文用系统字体渲染（`-apple-system` / `PingFang SC` / `Microsoft YaHei`），不加载外部字体。需要特殊字体时，把那一段做成图。
- 中英混排时中英文之间留空格；专有名词首次出现给英文原文。
- 术语先解释再用，别用行话省字。
- **话题标签：官方指导通篇未提**。它不在 X 官方长文方法论里，不要按小红书的习惯往正文堆标签。

## 5. 常见问题

| 现象 | 通常的原因 | 改法 |
|---|---|---|
| 发出去没人点 | 标题或第一段没有具体利益点 | 把「我们要讲什么」改成「你能得到什么」 |
| 点进来读两屏就走 | 前三分之一没有小结论 | 在第一节末尾先给一个结论 |
| 看起来很长很累 | 全文一个字号、没有节标题 | 加分节标题；段落压到 3–5 行 |
| 像内部文档 | 术语过多、缺背景 | 术语首次出现给解释；加一个具体例子 |
| 数据被质疑 | 没有出处或口径不清 | 补 FACTS 行；正文给来源与口径 |
| 手机上看排版乱 | 只在桌面检查 | 用手机实际打开编辑器预览 |

## 6. 交付清单

`export/x/article/`：

- `article.md` —— 正文全文（含标题、分节、正文图位置标记）
- `cover-169.jpg` —— 封面，16:9（建议 1200×675 或 1600×900）
- `meta.json` —— **自检脚本读它来校验字数与结构**，必须交付：

```json
{
  "form": "x/article",
  "purpose": "读完要 think: 这类方案都有隐藏成本 → do: 检查自己的迁移计划",
  "title": "文章标题（30–70 字符为宜）",
  "intro": "第一段（同时是时间线摘要）",
  "bodyChars": 2400,
  "sections": ["节标题 1", "节标题 2", "节标题 3"],
  "closeType": "question",
  "images": 4,
  "link": "https://example.com/related",
  "claim": true,
  "audience": "public"
}
```

字段说明：

| 字段 | 必填 | 用途 |
|---|---|---|
| `purpose` | ✅ | 官方第①条：读完要 think / feel / do 什么。缺它会提示「目的未声明」 |
| `closeType` | ✅ | 官方第⑧条：收尾类型 `summary` / `question` / `action`。缺它会提示「收尾未设计」 |
| `audience` | 建议 | `public`（默认）/ `subscribers`（订阅者可见） |
| `title` | ✅ | 标题长度校验 |
| `intro` | ✅ | 首段长度与「是否铺垫过久」提示 |
| `bodyChars` 或 `body` | ✅ | 正文字数校验（给了 `body` 取实际长度） |
| `sections` | 建议 | 分节标题；少于 2 个会提示结构过平 |
| `images` | 可选 | 配图数量 |
| `link` | 可选 | 文内主链接 |
| `claim` | 可选 | 是否含事实性主张；为 true 时必须有 FACTS 出处 |
| `boldInsights` | 可选 | 官方第③条：每节加粗的关键洞察数量；为 0 时会提示 |

---

## 7. 自检

```sh
python3 <skill-dir>/scripts/check_social_delivery.py --project <content-dir> \
  --forms x/article --strict
```

核对：标题与正文字数、封面比例、`meta.json` 结构、分节数量、`purpose` / `closeType` 是否声明、内部溯源（上屏数字能否在 `evidence/FACTS.md` 找到出处）。

**脚本只证明结构合规**，不证明写得好。发之前自己从手机完整读一遍。
